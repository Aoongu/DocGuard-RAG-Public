# Ragbits 基础复现结论

## 已验证

- 当前复现分支包含固定上游 commit `32074a71324239ba677234a67737ed65fb678eeb`；该 commit 的全部原始跟踪路径和 clean-filter 后的 blob 均保持一致，新增内容只允许位于 `reproduction/**` 和 `docs/superpowers/plans/**`。
- 三份本地 Markdown 经过上游 `DocumentSearch`、`FastEmbedEmbedder("BAAI/bge-small-en-v1.5")` 和 `InMemoryVectorStore` 摄取后，三条固定查询的 Top-1 依次为 `ragbits_overview.md`、`vector_store.md`、`evaluation.md`。
- 上游 `examples.chat.offline_chat:MyChat` 可以构造为 `RagbitsAPI`；`/openapi.json` 与 `/api/config` 在 FastAPI `TestClient` 中均返回 HTTP 200。
- `reproduction/tests`、两个复现脚本、JSON 字段/预期值、当前冻结环境中的结果文件运行前后哈希、完整上游树、新增路径白名单和新增文本密钥模式检查均由 `verify_reproduction.ps1` 联合验证。
- 离线上游单测的受控子集结果为 `148 passed, 7 deselected`；7 个排除项及原因已在 `environment.md` 和原始摘要中披露。

检索 JSON 中的 score 为负数并非错误。它保留了上游向量存储的距离/排序语义，只用于上游同一次排序；不能把该数值称为相似度概率，不能将 `-0.6` 解读为“负相关概率”，也不能据此宣称跨模型性能。

语义验证与字节稳定性并非同一结论：Top-1/HTTP 200 是必过条件；结果 JSON 字节哈希只证明当前冻结环境重复执行未变化。FastEmbed revision 未锁定，未来同名模型内容变化可能导致跨时间字节检查假失败，届时应核对模型来源并重新审查，而不是把字节差异直接解释为语义失败。

`reproduction/results/verification.txt` 实际验证的是功能复现提交 `39bcb5a67dd73db108708c41a2df4a766302c1c2`。包含说明和加固验证器的打包文档提交不能由其自身内部的已提交日志自证；最终交付 HEAD 与包哈希结果由交付包根级 `PACKAGE_VERIFICATION.txt` 在提交完成后外置记录。

## 未验证

- Docker 镜像、Compose 或容器部署（本机没有可用 Docker）。
- Ray 分布式摄取；固定锁文件中的 Ray 版本没有 Windows wheel。
- GCS、Unstructured、外部向量数据库、重排器、OCR、联网 LLM、云模型和完整在线对话。
- Linux/macOS 以及 Windows/Python 3.13 上完整 `uv sync --frozen`；该平台还遇到锁定 `safetensors` 的 wheel/源码构建问题。
- FastEmbed 模型的长期位级复现。模型名已固定，但远端模型 revision 未锁定，交付包也不含模型缓存。
- `uv pip check` 的三项不兼容未被修复：`fastapi-cloud-cli` 与 `typer` 的版本约束冲突，以及 `ragbits-document-search` 元数据所需的 `opencv-python`、`rerankers` 未安装。

## 不是二次开发

本成果是可审计的基础复现包，不是 DocGuard-RAG 功能实现。没有新增或声称完成 BM25+Dense 融合、RRF、Cross-Encoder 重排、拒答校准、gold 评测集、失败归因、生产 API、可观测性或部署工程。所有功能行为来自上游公开代码；本次新增内容仅包括最小输入、调用脚本、测试、结果证据、验证脚本和说明文件。

因此，可用于后续二次开发前的基线与环境审计，但不能作为“已完成二次开发”或“已获得业务性能提升”的证据。
