# DocGuard-RAG 1～2 分钟演示脚本

## 演示前准备

1. 按 [`docs/S11_DEPLOYMENT.md`](S11_DEPLOYMENT.md) 启动 API 与前端。
2. 确认 `/api/v1/health` 为 `ok`，PostgreSQL 17.11/18.6 两个语料版本可见。
3. 打开知识库、技术问答、证据检查器、评测看板四个页面。
4. 演示不运行 Test，也不触发批量真实 API 实验；只展示已冻结结果和单次交互查询。

## 讲解顺序

### 0～20 秒：问题与目标

“普通文档问答往往只返回一段看似合理的文本，但很难回答三个问题：答案来自哪一版文档、引用是否真的支持答案、证据不足时系统是否应该拒答。DocGuard-RAG 面向版本化技术文档，把快照、检索、引用验证、版本冲突和拒答评测放在同一条可审计链路中。”

### 20～45 秒：知识库与可追溯问答

在知识库页展示 PostgreSQL 17.11/18.6 和 7,413 个结构化 Chunk。

在问答页输入一个带版本的问题，例如：

> In PostgreSQL 17.11, what does auto_explain.log_min_duration do?

指出响应中的动作、原因码、版本、分阶段耗时和引用。点击引用进入证据检查器，展示官方 URL、章节路径、anchor、原文，以及 Dense/BM25/RRF/rerank 溯源。

### 45～70 秒：拒答与版本冲突

输入一个没有指定版本、但答案可能随版本变化的问题。展示系统返回 `clarify`，而不是替用户猜版本。

再输入超出 PostgreSQL 文档范围的问题，展示 `refuse`/失败关闭语义。说明拒答发生在生成前，引用验证发生在生成后，两者不是同一个步骤。

### 70～105 秒：冻结评测结果

切换到评测看板并展示：

- M2 Test nDCG@10 为 0.8298，但端到端 p50 为 12.85 秒。
- 完整 M4 在 60 题上拒答 F1 为 0.8657，失败 2 题；M3 失败 9 题。
- 五条在线路线总 API 成本约 0.155 美元。
- 人工复核 9 题，其中 3 题可评分，Faithfulness 和 Answer Relevance 均为 2.0/2.0。

同时指出负结果：Cross-Encoder 延迟高；一题 OOD 干净拒答与统一引用合同冲突；动作标签对一条实质澄清回答计分过严。

### 105～120 秒：个人贡献边界

“项目底层使用 Ragbits 的核心抽象，但文档冻结、双 tokenizer 切分、BM25/1wRRF、Cross-Encoder、拒答校准、一次性 Test 协议、FastAPI、React 界面和完整评测门禁均在 `src/docguard` 等自主区域实现。冻结的 Ragbits 复现代码单独放在 baseline 中，来源边界清晰。”

## 演示失败时的降级方案

- API 缺少模型或索引：展示健康检查的 `degraded` 状态和已冻结截图/图表，不伪装为在线可用。
- DeepSeek 不可用：不临时重跑正式实验，直接展示冻结的 Test 结果与原始 Evidence。
- Docker 不可用：使用 Windows 本地启动方式；两种方式都不把模型或密钥打入镜像。
